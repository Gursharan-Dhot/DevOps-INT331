Source Code Management with Git

Git is a distributed version control system that tracks changes in source code during software development. It's designed for coordinating work among programmers and tracking changes in files.

Key Features:

  • Distributed: Every developer has a complete copy of the project history
  • Branching: Create independent lines of development
  • Merging: Combine changes from different branches
  • Staging: Prepare changes before committing
git init # Initialize a new Git repository git clone [url] # Clone a remote repository git status # Check repository status git add [file] # Stage files for commit git commit -m "message" # Commit staged changes

Comparison Commands

Git provides powerful comparison tools to see differences between commits, branches, and working directory states.

Command Description Use Case
git diff Show unstaged changes Review changes before staging
git diff --staged Show staged changes Review changes before committing
git diff HEAD~1 Compare with previous commit See what changed in last commit
git diff branch1 branch2 Compare two branches See differences between branches
git diff --stat # Show file statistics git diff --name-only # Show only file names git diff --word-diff # Show word-level changes git diff [commit1] [commit2] # Compare specific commits

Branching Strategies

Branching allows you to create separate lines of development, enabling parallel work and feature isolation.

main → feature/login
develop → hotfix/bug-123
git branch # List all branches git branch [branch-name] # Create new branch git checkout [branch-name] # Switch to branch git checkout -b [branch-name] # Create and switch to branch git branch -d [branch-name] # Delete branch git branch -m [old] [new] # Rename branch

💡 Branching Best Practices

  • Use descriptive branch names (feature/user-auth, bugfix/login-error)
  • Keep branches focused on single features or fixes
  • Regularly sync with main branch
  • Delete merged branches to keep repository clean

Merging Techniques

Merging combines changes from different branches into a single branch, integrating parallel development work.

Types of Merges:

Fast-Forward Merge

When target branch hasn't diverged from source branch

git merge feature-branch # Fast-forward merge

Three-Way Merge

When both branches have diverged, creates a merge commit

git merge --no-ff feature-branch # Force merge commit

Squash Merge

Combines all commits from feature branch into single commit

git merge --squash feature-branch # Squash merge

🔄 Merge Conflict Resolution

When Git can't automatically merge changes:

  1. Edit conflicted files manually
  2. Remove conflict markers (<<<<<<<, =======, >>>>>>>)
  3. Stage resolved files with git add
  4. Complete merge with git commit

Rebasing

Rebasing rewrites commit history by moving commits from one branch to another, creating a linear history.

git rebase main # Rebase current branch onto main git rebase -i HEAD~3 # Interactive rebase last 3 commits git rebase --continue # Continue after resolving conflicts git rebase --abort # Abort rebase operation

Rebase vs Merge:

Aspect Rebase Merge
History Linear, clean Shows true history
Commits Rewrites commits Preserves original commits
Use Case Private branches Shared branches

⚠️ Rebase Golden Rule

  • Never rebase commits that have been pushed to shared repositories
  • Only rebase private, local branches
  • Use rebase for cleaning up commit history before merging

Stashing

Stashing temporarily saves your uncommitted changes, allowing you to work on something else and then restore them later.

git stash # Stash current changes git stash save "message" # Stash with message git stash list # List all stashes git stash apply # Apply latest stash git stash apply stash@{1} # Apply specific stash git stash pop # Apply and remove stash git stash drop # Delete latest stash git stash clear # Delete all stashes

🗃️ Stash Use Cases

  • Switch branches with uncommitted changes
  • Pull updates from remote repository
  • Quickly fix urgent bugs without committing current work
  • Experiment with code without losing current progress

Tagging

Tags are used to mark specific commits as important milestones, typically for releases or versions.

Types of Tags:

Lightweight Tags

Simple pointer to a commit

git tag v1.0 # Create lightweight tag

Annotated Tags

Full objects with metadata (recommended)

git tag -a v1.0 -m "Release v1.0" # Create annotated tag
git tag # List all tags git tag -l "v1.*" # List tags matching pattern git show v1.0 # Show tag information git push origin v1.0 # Push specific tag git push origin --tags # Push all tags git tag -d v1.0 # Delete local tag git push origin :refs/tags/v1.0 # Delete remote tag

Complete Git Workflow

1. Setup & Clone

git config --global user.name "Your Name" git config --global user.email "your.email@example.com" git clone https://github.com/user/repo.git

2. Create Feature Branch

git checkout -b feature/new-feature git push -u origin feature/new-feature

3. Make Changes & Commit

git add . git commit -m "Add new feature implementation" git push origin feature/new-feature

4. Sync with Main

git checkout main git pull origin main git checkout feature/new-feature git rebase main

5. Merge & Tag

git checkout main git merge feature/new-feature git tag -a v1.1 -m "Release v1.1" git push origin main --tags

🎯 Key Takeaways for Faculty

  • Git is essential for collaborative software development
  • Understanding branching strategies improves code organization
  • Regular commits with clear messages maintain project history
  • Rebasing creates cleaner history but should be used carefully
  • Stashing provides flexibility for handling interruptions
  • Tags mark important milestones and releases
  • Comparison commands help understand code evolution
