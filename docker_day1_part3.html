🧪 Command Line Verification Tests

Run these commands in PowerShell or Command Prompt to verify your installation:

Test 1: Check Docker Version

PS C:\> docker --version Docker version 24.0.7, build afdd53b PS C:\> docker version Client: Version: 24.0.7 API version: 1.43 Go version: go1.20.10 Git commit: afdd53b Built: Thu Oct 26 09:08:44 2023 OS/Arch: windows/amd64 Context: default Server: Docker Desktop 4.25.0 (126437) Engine: Version: 24.0.7 API version: 1.43 (minimum version 1.12) Go version: go1.20.10 Git commit: 311b9ff Built: Thu Oct 26 09:08:02 2023 OS/Arch: linux/amd64 Experimental: false

✅ Expected Result

Both client and server information should be displayed, confirming Docker Desktop is running.

Test 2: System Information

PS C:\> docker info # Key information to verify: # Containers: 0 running, 0 paused, 0 stopped, 0 total # Images: [number] # Server Version: 24.0.7 # Storage Driver: overlay2 # Operating System: Docker Desktop # OSType: linux # Architecture: x86_64 # CPUs: [your CPU count] # Total Memory: [your allocated memory]

Test 3: Hello World Container

PS C:\> docker run hello-world # Expected output: Hello from Docker! This message shows that your installation appears to be working correctly. To generate this message, Docker took the following steps: 1. The Docker client contacted the Docker daemon. 2. The Docker daemon pulled the "hello-world" image from the Docker Hub. 3. The Docker daemon created a new container from that image which runs the executable that produces the output you are currently reading. 4. The Docker daemon streamed that output to the Docker client, which sent it to your terminal.

🎉 Success!

If you see the "Hello from Docker!" message, your installation is working perfectly!

Test 4: Interactive Container

PS C:\> docker run -it ubuntu bash # You should enter the Ubuntu container terminal: root@[container-id]:/# whoami root root@[container-id]:/# cat /etc/os-release NAME="Ubuntu" VERSION="20.04.6 LTS (Focal Fossa)" root@[container-id]:/# exit PS C:\>

✅ Verification Complete

If you can enter and exit the Ubuntu container, Docker is working correctly!

🛠️ Troubleshooting Common Issues

Problem Symptoms Solution
Docker Desktop won't start Whale icon shows error or keeps loading • Check Windows version (19041+)
• Enable virtualization in BIOS
• Run as Administrator
• Restart Windows
WSL 2 installation failed "WSL 2 installation is incomplete" • Download WSL 2 kernel update manually
• Run: wsl --update
• Enable "Virtual Machine Platform" feature
• Restart computer
Permission denied errors "docker: permission denied" in PowerShell • Add user to "docker-users" group
• Log out and log back in
• Restart Docker Desktop
• Run PowerShell as Administrator
Containers won't start Container exits immediately with error • Check available disk space
• Increase memory allocation
• Disable antivirus real-time scanning
• Reset Docker to factory defaults
Slow performance Containers start slowly or run sluggishly • Use WSL 2 backend instead of Hyper-V
• Increase CPU/memory allocation
• Store project files in WSL filesystem
• Disable unnecessary file sharing
Network connectivity issues Cannot pull images or reach external services • Check firewall settings
• Configure proxy if needed
• Reset network settings in Docker
• Restart Docker Desktop

🆘 Advanced Troubleshooting Commands

# Reset Docker Desktop to factory defaults # Go to Settings → Troubleshoot → Reset to factory defaults # Check Docker Desktop logs PS C:\> Get-Content "$env:APPDATA\Docker Desktop\log\vm\dockerd.log" -Tail 50 # Restart Docker Desktop service PS C:\> Restart-Service -Name "com.docker.service" # Check WSL 2 status PS C:\> wsl --status # Update WSL 2 PS C:\> wsl --update PS C:\> wsl --shutdown

⚙️ Essential Configuration & Settings

🔧 Resources Configuration

Optimize performance for your system:

  • CPU: Allocate 2-4 cores (50-75% of total)
  • Memory: 4-6GB (50% of system RAM)
  • Swap: 1-2GB for memory overflow
  • Disk Image Size: 64GB default

⚠️ Resource Allocation

Don't allocate more than 75% of your system resources to Docker.

📁 File Sharing

Configure folder access:

  • C:\ - Usually enabled by default
  • Custom folders - Add as needed
  • Performance: Limit shared folders
  • Security: Only share necessary directories
