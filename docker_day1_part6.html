🧪 Lab 1: Your First Web Server

1

Deploy a Web Server with Custom Content

Learn basic container operations and file management

🎯 Objective: Deploy an Nginx web server, customize its content, and make it accessible from your Windows host.
Pull the Nginx Image

Download the official Nginx image from Docker Hub:

# Pull the lightweight Alpine version docker pull nginx:alpine # Verify the image is downloaded docker images nginx
Expected output: REPOSITORY TAG IMAGE ID CREATED SIZE nginx alpine a6eb2a334a9f 2 weeks ago 23.4MB
Run the Container

Start Nginx container with port mapping:

# Run nginx in background on port 8080 docker run -d -p 8080:80 --name my-web-server nginx:alpine # Check if container is running docker ps
✅ Verification

Open your browser and go to http://localhost:8080

You should see the "Welcome to nginx!" page

Customize the Web Content

Create custom HTML content and copy it to the container:

# Create a custom HTML file on Windows echo "<h1>Hello from Docker!</h1><p>This is my first containerized web server.</p>" > index.html # Copy the file to the container docker cp index.html my-web-server:/usr/share/nginx/html/ # Verify the file was copied docker exec my-web-server ls -la /usr/share/nginx/html/
✅ Verification

Refresh your browser at http://localhost:8080

You should now see your custom "Hello from Docker!" message

Explore Container Internals

Access the container's shell and explore:

# Get an interactive shell inside the container docker exec -it my-web-server sh # Inside the container, run these commands: whoami pwd ls -la /usr/share/nginx/html/ cat /etc/nginx/nginx.conf | head -20 ps aux exit
💡 What You're Learning

You're exploring the container's isolated environment, seeing that it has its own filesystem, processes, and configuration separate from your Windows host.

Monitor and Clean Up

Check container resource usage and clean up:

# Check resource usage docker stats my-web-server --no-stream # View container logs docker logs my-web-server # Stop the container docker stop my-web-server # Remove the container docker rm my-web-server # Clean up the local file del index.html
🎉 Lab 1 Complete!

You've successfully deployed, customized, and managed your first containerized web server!

🔧 Common Issues
  • Port 8080 already in use: Try port 8081: -p 8081:80
  • Cannot access website: Check Windows Firewall or use 127.0.0.1:8080
  • File copy fails: Ensure container is running when using docker cp

🧪 Lab 2: Database Container with Persistent Data

2

MySQL Database with Volume Persistence

Learn about data persistence and environment variables

🎯 Objective: Set up a MySQL database container with persistent storage and connect to it from your host machine.
Create a Data Volume

Create a Docker volume for persistent database storage:

# Create a named volume for database data docker volume create mysql-data # List volumes to verify creation docker volume ls # Inspect the volume details docker volume inspect mysql-data
Expected output shows volume location: "Mountpoint": "/var/lib/docker/volumes/mysql-data/_data"
Run MySQL Container

Start MySQL with environment variables and volume mount:

# Run MySQL with persistent storage docker run -d \ --name my-database \ -e MYSQL_ROOT_PASSWORD=rootpassword \ -e MYSQL_DATABASE=testdb \ -e MYSQL_USER=testuser \ -e MYSQL_PASSWORD=testpass \ -p 3306:3306 \ -v mysql-data:/var/lib/mysql \ mysql:8.0 # Check if container started successfully docker ps docker logs my-database
✅ Verification

Wait for the log message: "MySQL init process done. Ready for start up."

This may take 1-2 minutes on first startup.

Connect and Create Data

Connect to MySQL and create some test data:

# Connect to MySQL as testuser docker exec -it my-database mysql -u testuser -ptestpass testdb # Inside MySQL, run these commands: SHOW DATABASES; USE testdb; CREATE TABLE users ( id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(50), email VARCHAR(100) ); INSERT INTO users (name, email) VALUES ('John Doe', 'john@example.com'), ('Jane Smith', 'jane@example.com'); SELECT * FROM users; EXIT;
Expected output: +----+------------+------------------+ | id | name | email | +----+------------+------------------+ | 1 | John Doe | john@example.com | | 2 | Jane Smith | jane@example.com | +----+------------+------------------+
Test Data Persistence

Restart the container and verify data persistence:

# Stop and remove the container docker stop my-database docker rm my-database # Start a new container with the same volume docker run -d \ --name my-database-v2 \ -e MYSQL_ROOT_PASSWORD=rootpassword \ -e MYSQL_DATABASE=testdb \ -e MYSQL_USER=testuser \ -e MYSQL_PASSWORD=testpass \ -p 3306:3306 \ -v mysql-data:/var/lib/mysql \ mysql:8.0 # Wait for startup, then check our data is still there docker exec -it my-database-v2 mysql -u testuser -ptestpass testdb # In MySQL: SELECT * FROM users; EXIT;
🎉 Data Persisted!

Your data survived the container restart because it's stored in the Docker volume, not inside the container.

Clean Up Resources

Remove containers and volumes:

# Stop and remove container docker stop my-database-v2 docker rm my-database-v2 # Remove the volume (this will delete the data!) docker volume rm mysql-data # Verify cleanup docker ps -a docker volume ls
🎉 Lab 2 Complete!

You've mastered data persistence with volumes and environment variable configuration!

🔧 Common Issues
  • MySQL won't start: Check logs with docker logs my-database
  • Connection refused: Wait longer for MySQL initialization (check logs)
  • Port 3306 in use: Use different port: -p 3307:3306
  • Volume permission issues: This is normal on first run, MySQL will fix permissions

🧪 Lab 3: Multi-Container Application

3

WordPress with MySQL Backend

Learn container networking and multi-service deployment

🎯 Objective: Deploy a complete WordPress website with MySQL database backend, demonstrating container-to-container communication.
Create a Custom Network

Create a network for container communication:

# Create a custom bridge network docker network create wordpress-network # List networks to verify creation docker network ls # Inspect the network details docker network inspect wordpress-network
💡 Why Custom Networks?

Custom networks allow containers to communicate using container names as hostnames, making configuration easier and more reliable.

Deploy MySQL Database

Start MySQL container on the custom network:

# Run MySQL for WordPress docker run -d \ --name wordpress-db \ --network wordpress-network \ -e MYSQL_ROOT_PASSWORD=rootpass \ -e MYSQL_DATABASE=wordpress \ -e MYSQL_USER=wpuser \ -e MYSQL_PASSWORD=wppass \ -v wordpress-db-data:/var/lib/mysql \ mysql:5.7 # Check database container status docker ps --filter name=wordpress-db docker logs wordpress-db --tail 10
✅ Verification

Wait for the log message indicating MySQL is ready for connections.

Deploy WordPress Application

Start WordPress container and connect it to MySQL:

# Run WordPress connected to our database docker run -d \ --name wordpress-app \ --network wordpress-network \ -p 8080:80 \ -e WORDPRESS_DB_HOST=wordpress-db:3306 \ -e WORDPRESS_DB_USER=wpuser \ -e WORDPRESS_DB_PASSWORD=wppass \ -e WORDPRESS_DB_NAME=wordpress \ wordpress:latest # Check both containers are running docker ps
Expected output shows both containers running: CONTAINER ID IMAGE COMMAND STATUS abc123def456 wordpress "docker-entrypoint.s…" Up X minutes 789ghi012jkl mysql:5.7 "docker-entrypoint.s…" Up X minutes
Access WordPress Setup

Complete WordPress installation through the web interface:

✅ Website Access
  1. Open browser and go to http://localhost:8080
  2. You should see WordPress setup wizard
  3. Follow the setup process:
    • Choose language
    • Set site title: "My Docker WordPress"
    • Create admin user and password
    • Complete installation
# Monitor both containers docker logs wordpress-app --tail 20 docker logs wordpress-db --tail 20 # Check network connectivity docker exec wordpress-app ping -c 3 wordpress-db
Test the Complete Application

Verify the multi-container application works:

✅ Functionality Test
  1. Log into WordPress admin at http://localhost:8080/wp-admin
  2. Create a new post with title "Hello Docker World!"
  3. Add some content and publish the post
  4. View the post on the main site
  5. Verify data persistence by restarting containers
# Test container communication docker exec wordpress-app nc -zv wordpress-db 3306 # Check resource usage docker stats --no-stream # View network details docker network inspect wordpress-network
Clean Up Multi-Container Setup

Remove all components of the application:

# Stop all containers docker stop wordpress-app wordpress-db # Remove containers docker rm wordpress-app wordpress-db # Remove the custom network docker network rm wordpress-network # Remove the volume (optional - this deletes all data!) docker volume rm wordpress-db-data # Verify cleanup docker ps -a docker network ls docker volume ls
🎉 Lab 3 Complete!

You've successfully deployed and managed a multi-container application with database backend!

🔧 Common Issues
  • WordPress shows database connection error: Wait for MySQL to fully initialize
  • Containers can't communicate: Ensure both are on the same network
  • Website loads slowly: WordPress container may be downloading/installing
  • Port 8080 unavailable: Try 8081 or check what's using the port

🔄 Container Lifecycle Mastery

🎯 Complete Lifecycle Practice

Practice every stage of container lifecycle management with this comprehensive exercise.

CREATED
→
docker create
Container exists but is not running
RUNNING
→
docker start / docker run
Container is executing and operational
PAUSED
→
docker pause
Container processes are suspended
STOPPED
→
docker stop
Container has exited gracefully
# Complete lifecycle practice # 1. Create without starting docker create --name lifecycle-demo nginx:alpine # 2. Check status (should show Created) docker ps -a --filter name=lifecycle-demo # 3. Start the container docker start lifecycle-demo # 4. Verify it's running docker ps --filter name=lifecycle-demo # 5. Pause the container docker pause lifecycle-demo # 6. Check status (should show Paused) docker ps -a --filter name=lifecycle-demo # 7. Unpause the container docker unpause lifecycle-demo # 8. Stop the container gracefully docker stop lifecycle-demo # 9. Check final status (should show Exited) docker ps -a --filter name=lifecycle-demo # 10. Remove the container docker rm lifecycle-demo # 11. Verify removal docker ps -a --filter name=lifecycle-demo

You've successfully practiced every stage of container lifecycle management!

🚀 Build a Complete Development Environment

Put everything together in this comprehensive final challenge

🎯 Project Requirements

Create a multi-container development environment with the following components:

🌐 Web Server
  • Nginx serving custom HTML
  • Accessible on port 8080
  • Custom welcome page
  • Named "dev-web"
🗄️ Database
  • MySQL 8.0 container
  • Persistent data storage
  • Sample database and table
  • Named "dev-db"
🔍 Monitoring
  • Redis for caching
  • Accessible on port 6379
  • Test data insertion
  • Named "dev-cache"
🌐 Networking
  • Custom network "dev-network"
  • All containers connected
  • Inter-container communication
  • Network isolation

📋 Step-by-Step Implementation

# Step 1: Create the network docker network create dev-network # Step 2: Create volumes for persistence docker volume create dev-mysql-data docker volume create dev-web-content # Step 3: Deploy MySQL database docker run -d \ --name dev-db \ --network dev-network \ -e MYSQL_ROOT_PASSWORD=devroot123 \ -e MYSQL_DATABASE=devdb \ -e MYSQL_USER=devuser \ -e MYSQL_PASSWORD=devpass123 \ -v dev-mysql-data:/var/lib/mysql \ mysql:8.0 # Step 4: Deploy Redis cache docker run -d \ --name dev-cache \ --network dev-network \ -p 6379:6379 \ redis:alpine # Step 5: Create custom HTML content echo "<!DOCTYPE html> <html> <head><title>Dev Environment</title></head> <body> <h1>🚀 Development Environment</h1> <p>Multi-container setup complete!</p> <ul> <li>Web Server: ✅ Online</li> <li>Database: ✅ Connected</li> <li>Cache: ✅ Ready</li> </ul> </body> </html>" > dev-index.html # Step 6: Deploy Nginx web server docker run -d \ --name dev-web \ --network dev-network \ -p 8080:80 \ nginx:alpine # Step 7: Copy custom content to web server docker cp dev-index.html dev-web:/usr/share/nginx/html/index.html # Step 8: Verify all containers are running docker ps # Step 9: Test inter-container communication docker exec dev-web ping -c 3 dev-db docker exec dev-web ping -c 3 dev-cache # Step 10: Test database connection docker exec -it dev-db mysql -u devuser -pdevpass123 devdb # In MySQL, create test data: CREATE TABLE developers ( id INT PRIMARY KEY AUTO_INCREMENT, name VARCHAR(50), skill VARCHAR(50) ); INSERT INTO developers (name, skill) VALUES ('Alice', 'Docker'), ('Bob', 'Kubernetes'), ('Carol', 'DevOps'); SELECT * FROM developers; EXIT; # Step 11: Test Redis cache docker exec -it dev-cache redis-cli # In Redis: SET app:status "running" SET app:version "1.0.0" GET app:status KEYS app:* EXIT # Step 12: Access the web application # Open browser to http://localhost:8080

✓ All three containers running successfully
✓ Custom network connecting all services
✓ Web server displaying custom content
✓ Database with sample data created
✓ Redis cache storing test data
